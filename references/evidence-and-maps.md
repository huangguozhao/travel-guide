# 可信资料与真实地图

## 事实台账：只记影响出行决定的内容

台账可为 Markdown 表或 JSON，放在工作目录。每条包含：事实 / 操作、地点或路段、来源标题和直达 URL、发布或更新时间（若可得）、查阅日期、适用日期 / 对象、状态、对路线的影响。机器可读状态统一为 `verified`（来源直接支持）、`estimated`（导航或规划估计）、`unknown`（合理核实后仍未知）、`login_required`（登录、验证码或权限阻断）；历史、传说与用户已确认另作说明。

例：来源说“某个假期延长营业”，适用范围就是该假期；不能据此写全年晚间开放。来源日期新，也不代表其中所有老内容已更新。

优先级：

1. 运营方、政府、交通公司、景区认证账号、官方订票平台、官方地图。
2. 项目参与单位或权威媒体，对其亲历 / 负责的事实使用。
3. 本地宝、攻略平台、小红书和个人帖子，只作补充，标明转引或个人体验。当天规则和费用仍回到官方或现场核实。

搜索摘要用来发现材料，尽量打开原文，核对日期、范围与是否旧版。只看过摘要的资料要记录证据限制。用户要帖子教程链接时，给真实可访问的帖子或教程，别编帖子 ID；帖子不替代官方规则。

## 有界核实：查到足够，而不是查到疲惫

对会改变路线、预算、入场或安全的事实，至少尝试：换一次查询表达、换一个来源类别、换一个当前允许的访问通道。仍无法确认时停止，把尝试、阻断原因和用户最小复核动作写入台账；`unknown` 与 `login_required` 都是有效结果，不用更多低质量页面把它“冲淡”。

同一页面的搜索摘要、转载和缓存不是三个来源。官方页面已经直接回答且无冲突时无需机械双源；高风险规则、明显冲突、昂贵预订或关键闭馆信息才提高核实强度。可选点长期无法确认则降级，关键交通或入场前提无法确认则换成有证据的方案或向用户说明阻断。

## 动态信息的使用边界

- 有明确旅行日期才查该日时刻与票价；余票、预约空位还要记录查询时间。只查到通常班次时，显示官方查询路径，不写成已订到的车次。
- 门到门时间 = 起点接驳 + 安检 / 候车 + 乘车 + 到达接驳。候车和缓冲为策划值，单独标注；导航预测不是实测。
- 预约说明区分免费票、付费体验、讲解 / 研学、联票、日场与夜场；街区可以通行不证明内部馆可进。菜单、证件核验方式和可预约人数只写当前有证据的版本。
- 地铁主线 / 支线、方向、跨城支付和新开车站需要现行资料。火车站名必须与车票匹配；“XX”和“XX北”不能互换。
- 价格标清日期、币种、单位与包含项。没有菜单证据就写预算估计，不能混入商户实时数据列。全组船费、个人餐费、购物与应急费用分别计算。
- 未核实的门店评分、队长、营业时间、入口编号保持空缺，给查证方法；不要将地址相近或名称相似的商户合成一家。
- 跨境证件、通信套餐、海关、铁路携带物品等规则以对应主管方 / 运营商现行资料为准；套餐适用号码、激活时点、计费与手机设置须分别核实，不移植另一运营商教程。

遇到来源冲突，先比较是否同日期、同入口 / 票种、同交通交路，再找运营方当前通知。经过几个针对性的官方渠道仍无法确认，就显式标待确认：可选点降级，关键交通 / 入场前提则请求用户补充或提出已有证据的替代路径，不靠猜测闭环。

## 地图：底图、地点和路线分别核验

用户指定地图平台时优先按其选择制作，仍须满足真实性、许可、署名和可验证性要求。用户未指定平台时，中国内地攻略采用以下无 Key 截图顺序：

1. **高德地图网页版**：在真实网页中按地点名称搜索，使用网页自身的步行 / 公交 / 驾车路线和标记，截取可见地图。
2. **百度地图网页版**：高德无法访问、无法完整显示所需路线或地点核验不足时使用。
3. **腾讯地图网页版**：作为第二备用来源，仍使用网页自身地点和路线结果。
4. **OpenStreetMap + OSRM 兜底**：前三者受登录、验证码、反自动化、页面兼容或可用性限制时，使用真实 OpenStreetMap 底图、核实的 POI 与 OSRM 对应交通模式路线，生成可控标注图后截图。

网页版截图不需要地图 Web 服务 API Key；它也不等于可以匿名调用平台的编程接口、批量抓取瓦片或绕开访问限制。若用户要求 API、批量生成或动态嵌入，再核实平台当前开发者 Key、额度和许可条件。地图网页要求登录、出现验证码或阻止自动化时，不绕过，按上述顺序切换并在成品中准确注明实际来源。中国内地以外的路线选择当地可用且授权清楚的地图服务，用户选择仍优先。

无论使用哪一平台，采用这条制作链：

1. 获取有明确提供者和许可的真实底图。官方景区导览也可用，但保留其范围和更新时间；不假定有重发布许可。
2. 检索真实 POI，校验城市、同名地点、类型与位置。高德、百度、腾讯优先以平台自己的地点搜索与路线结果为准；不知道入口就标场馆或站体，不把中心点装作入口。
3. 坐标与底图必须采用一致体系：OpenStreetMap 通常使用 WGS84，高德 / 腾讯常见 GCJ-02，百度常见 BD-09，不能直接混用。跨平台制作优先用地点名称重新搜索，不把一家的坐标原样叠到另一家的底图。
4. 使用地图平台自身显示的真实步行 / 公交 / 驾驶路线；使用 OpenStreetMap 兜底时才以 OSRM 返回的相应路线几何绘制红线。标注交通模式、来源、制作日期和距离。直线连点只能作为示意，并明确不是导航路线。水上航线需独立运营依据，不由陆路点位推测。
5. 按旅途顺序加编号、关键站名、方向与简短任务。优先保留平台已有地点标记和路线；若截图后补充编号、箭头或文字，不改写道路形状，也不遮住关键地名。覆盖复杂时分成几段，编号与正文保持一致，避免把编号读成地铁出口号。
6. 通过授权的浏览器机制截取当前可见地图；确认底图瓦片、地点名称和整条路线已经加载，路线没有被面板或视口裁掉。地图过长时分段截图，不用过度缩小换取“一张全塞下”。
7. 保留平台 Logo、版权 / 数据来源、比例尺等可见署名，不通过裁切、涂抹或重新排版隐藏。内嵌截图时附提供者名称、原地图 / 导航链接、查询或制作日期；说明路线是规划而非实测，临时导流、施工、封闭入口可能不在图上。公开发布或商业使用前，另核对平台当时的截图与重发布条款。

可给地图侧栏 / 全屏放大，手机应能放大后横纵滑动；同时在正文列编号地点，让用户不必从缩略图猜字。截图不可用时给可核实的文字步骤与地图链接，说明缺口；不要以伪地图补齐。

地图访问需要登录或触发限制时，尊重工具与账号边界。换用备用地图或 OpenStreetMap + OSRM 兜底时，在图注中明确提供者变化；不会隐藏来源以假装截图来自用户指定服务。兜底图必须保留 OpenStreetMap attribution，并标出 OSRM 只负责路线规划；不要把它称作高德、百度、腾讯或 Google 地图截图。

## 照片与许可

- 首选自己获准使用的照片、用户提供素材或有明确许可的图库，例如 Wikimedia Commons 的具体文件页；核对照片是否真是该地点。
- 同时保存原图页、作者、许可链接、拍摄年代（若可得）和修改说明。地图标注、裁切或衍生图遵守原许可和适用署名要求。
- 官网配图可以用于查证，但不因公开可访问就自动获得下载、复制或重发布权限。来源页面的介绍与照片许可分别判断。
- 老照片标历史实拍，不代表当前入口、水位或商户。通用菜式照片标示意 / 非指定餐厅出品；没有照片时用文字或图标即可，不能编造餐厅出品照片。
- AI 插画仅在用户愿意接受装饰图时使用，并标为插画；不作为景点现场、菜品出品或地图依据。涉及图片生成 / 编辑时使用环境中适用的技能和工具。

### 实景覆盖表

`rich` 攻略在制作 HTML 前为每个核心 POI 建一行：`stop_id / 具名地点 / 照片主题 / 原文件页 / 作者 / 许可 / 拍摄年代 / 修改 / 本地资产 / subject_verified`。照片必须能从文件页、说明或可靠元数据确认是该具名地点；HTTP 200、文件名相似或“看起来像”都不算主题核实。

地图、路线截图、菜单截图、票务二维码和通用城市天际线不计入核心 POI 的实景照片覆盖。照片显示建筑旧貌、季节性布置或历史状态时在图注标日期边界。一个核心 POI 暂无可合法内嵌的照片时，保留正文与原页面链接并显示缺口原因；不要因此删除该 POI 的现场说明，也不要用另一地点或生成图占位。

## 从证据回到路线

资料完成后重新计算：最早可到达时间是否落在预约窗内？上午走路加参观是否留得下午餐？两个晚间项目是否挤占返程？必须提前入园 / 进站与建议缓冲是否混为一谈？新增点靠删掉哪个旧点容纳？

只有每项关键前提已核实或明示受哪些未知条件制约，才进入“可执行成品”阶段。
