# HTML 成品与验收

## 按旅行任务组织页面

根据行程选用以下模块，不必机械全部出现：

- 开头：目的地、起点、日期 / 未定、天数、路线速览、核心体验和关键假设。
- 出发前：需要预约的事、证件 / 随身物品、实际交通选择。
- 当天时间线：每段怎么到、看什么、何时离开、集合参照和可选点。
- 地图：真实标注截图，与时间线编号相互对应；需要时展开侧栏。
- 吃什么：菜式、用餐位置、点单思路、预算单位；具名门店保持证据边界。
- 手信：轻便、储存、包装、实际适用的携带要求。
- 回程与替代：不可错过的约束，以及雨天 / 晚到 / 疲惫的删减方案。
- 预算与来源：计划价格和实际价格分开，链接、核对时间、图片来源与未确认项。

以中文表达现场任务，装饰性英文不能成为唯一导航文字。手机文字可读、触控目标足够，时间与地点能快速扫描；长列表分段，避免水平表格承载核心信息。风格依用户偏好和目的地调整，不把这一次的江南配色变成通用要求。

### 三种输出契约

- `quick`：只交付用户所问的推荐、路线或事实；无需伪装成完整攻略。
- `standard`：路线、时间线、关键地点、必要地图、来源、预算和替代方案齐全；媒体按任务需要选择。
- `rich`：在 `standard` 上逐点补足现场观察、抵达参照、停留 / 离开条件、停车或换乘、拍照位置、真实实景图及其来源。每个核心地点至少一张真实照片；许可不明不算图片缺口，只有无法找到可确认地点的照片时才显示缺口。

“随便逛”表示节奏宽松，“半日 / 一日”表示时间边界，都不改变用户明确指定的 `rich` 成品。完整度按核心地点覆盖率判断，不按总字数判断。

## 单文件离线阅读

CSS、脚本写在文件内；必要图片、地图用 data URI。来源、订票、预约、天气和导航是联网功能，说明两者区别。避免外部字体和 CDN 成为阅读前提。较大图片先合理缩放 / 压缩，再打包，保持可读地图标注和可追溯来源；目标是易分享，不是固定大小限制。

附带 `scripts/html_bundle.py` 支持两种命令：

```text
python <skill-dir>/scripts/html_bundle.py pack work/source.html --out outputs/攻略.html
python <skill-dir>/scripts/html_bundle.py audit outputs/攻略.html --report work/qa.json
```

源码中 `src="{{asset:assets/map.png}}"` 按源码目录解析并内嵌，或用 `--asset-root <dir>` 改根目录。只允许根目录内的 PNG / JPEG / GIF / WebP 图片，禁止跨目录读取；无网络请求。已有输出需显式 `--overwrite`。遇到编码或未替换占位符报错，修源码再执行。

该检查能发现页内目标缺失、重复 ID、外部渲染资源、损坏的内嵌图片编码等静态问题，但不检查价格真伪、照片地点是否正确、路线安全、运行时行为或真实浏览器效果。

`standard` / `rich` 页面配合 `trip-data.json`：每个核心地点的根元素使用 `data-stop-id="..."`，每张受控照片或地图使用 `data-media-id="..."`。这些属性服务于覆盖验证，不替代可见标题、图注和无障碍替代文本。

## 交互的使用条件

只加能帮助出行的交互：

- 路线速览：电脑可悬停，手机可点；不能只有 hover 才有信息。键盘可进入，正文仍保留任务。
- 地图 / 地点侧栏：点击有清晰名称；关闭、遮罩、Escape 与焦点返回有效。手机不溢出视口，缩放后可滑动，正文无脚本时也有图片与地点说明。仅由脚本赋值 `src` 的弹窗图片标记 `data-dynamic-image`，让静态审计能区分有意动态图片与漏写资源。
- 交通切换：选中状态、面板标题与实际内容一致，打印时保留需要的方案。
- 准备清单与备注：本地保存可选，说明不会上传；敏感证件数据不放进攻略。`file://` 的 localStorage 支持因浏览器而异，不作必然承诺。
- 分享填写结果：若有“下载已填写”按钮，导出当前输入、复选框与选择值；不能只保存原始源码。清理展开弹窗 / 禁滚动等临时状态，避免重复内嵌图片。告知导出文件含用户填写内容。
- 预算：每人费用 × 人数 + 全组费用，分母清晰；验证空值、人数下限与小数处理，不重复累计船费 / 往返票。
- 返程倒推：开车时间 − 站内余量 − 离城接驳余量。余量是规划值，计算器不代表已查询车次或赶车保证；跨午夜应标日期归属。

旅途中需要频繁点击的按钮和链接以 44×44 CSS px 为最低触控目标；纯正文链接可不强行方形化，但行距和周围空白要避免误触。地图放大、弹窗关闭、日程切换和导航链接在窄屏浏览器中逐个实际量测，不以 CSS 声明代替布局结果；尤其不要只量主页面按钮而漏掉弹窗右上角关闭按钮。

界面展示的假设、计算结果与用户填写状态保持一致。校验无效输入并给解释，不偷偷用一个看不见的修正值算“确定结果”。

## 验收顺序

1. **内容**：核实站名、方向、预约与票种；把所有时间段加起来；检查地图编号、费用单位及每个来源的适用期。逐行核对核心地点覆盖矩阵；尚未确认的条件仍可见。
2. **数据契约**：运行 `validate_trip_data.py`，先检查地点、路段、媒体、来源和替代方案，再用 `--html` 核对页面是否实际渲染全部核心地点与受控媒体。
3. **结构**：运行静态检查；正文的图片和链接存在，没有漏替换占位符。外链可访问性按影响出行的程度检查，链接存在不等于已核实内容。
4. **桌面**：浏览器打开实际交付文件或其本地 HTTP 等价路径；检查顶部、交通、时间线、地图、食物卡与来源。若浏览器控制面拒绝 `file://`，在工作目录启动只读本地 HTTP 服务并加载同一成品，不把协议限制误报成页面故障。
5. **手机宽度**：至少一个典型窄屏；必要时更窄屏 / 平板。检查标题、表单、地图 / 侧栏、导航的溢出、字号和核心触控目标。浏览器不支持视口设置时，用工作目录中的固定宽度 iframe 加载同一文件做布局检查；不把它称为手机实机测试。
6. **行为**：实际点击使用到的按钮与展开项；修改人数 / 金额 / 车票时间，手算一组结果核对；如果有导出，核对导出状态。检查错误日志、键盘关闭、焦点恢复和无脚本阅读基础。
7. **分享**：确认成品不引用工作目录下的图片 / CSS / 脚本。内嵌图片若用了 lazy loading，要在对应位置确认已加载，不能把“尚未滚到”误报损坏。检查离线读取和打印是否为本次声称支持的功能。

源码变更后重新构建 / 打包，再重新加载实际成品，检查受影响的区域；旧截图不能证明新文件正确。浏览器操作使用当前环境提供的技能，不把某一会话里的标签页 ID、端口、工具句柄或限制写死到通用实现。

工具无法完成某项验证时，保留成品并准确报告已验证范围及未验证项；不换一个未获准的浏览器控制机制绕过限制。

## 交付边界

成品仅放用户输出目录；中间 HTML、事实台账、图片来源记录、资产与测试报告放工作目录。完成后给可点击的绝对文件链接、安排假设，以及关键待确认项。通常一份最终 HTML 就够；用户要求才另外交付 PDF、部署网站或分享公开链接。

旧攻略的更新先列 section inventory：页面现有章节、核心地点、实景图、地图、交互、用户填写与已验证事实。更新后逐项对比，除用户要求删除的内容外不得无声减少；对变更的日期 / 城市 / 交通相关事实重新核实。生成攻略不构成订票、预约、付款、获取用户隐私或公开发布的授权。
